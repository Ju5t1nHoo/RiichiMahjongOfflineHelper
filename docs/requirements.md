# 立直麻将线下 H5 计分工具 — 需求规格说明书

> 版本：v0.1（经需求分析访谈确认）
> 配套文档：`CONTEXT.md`（术语表）、`docs/adr/0001`、`docs/adr/0002`

## 1. 概述

**产品定位**：帮助线下日麻牌局记录分数与顺位、并为注册用户沉淀雀士数据与统计的 H5（移动端网页）工具。

**本质边界**：这是一个「点数计算器 + 牌局记录器」，**不是规则判定引擎**（见 ADR-0001）。吃碰杠、役种判定、宝牌、拔北等牌面机制一律不建模——它们最终都折算为「番」，由玩家在输入时自行核算，工具只负责算钱、记分、统计。

**范围外**：不含在线对局、不含发牌/摸牌、不含役种提示、不含 AI。

## 2. 功能模块总览

| 模块 | 是否需登录 | 说明 |
|---|---|---|
| 计分风盘 | 否（游客可用） | 核心计分；游客可临时打分、不持久化（保存需登录） |
| 牌局录分 | 是 | 快速录分：直接录入终局素点 + 基础分/返点/马点，校验总分后落库并计入统计 |
| 数据统计 | 是 | 我的创建 / 数据广场 / 雀士数据 |
| 个人中心 | 是 | 签名、雀士管理、规则默认设置、改密、反馈 |

四个模块通过**底部标签栏**切换（计分风盘 / 牌局录分 / 数据统计 / 个人中心），计分风盘为默认首页；牌局录分、数据统计、个人中心需登录，未登录点选进登录/注册页。计分风盘为沉浸式界面：牌局**进行中**自动隐藏底部标签栏（开局页与终局后仍显示），进行中顶栏「返回」键重新显示标签栏。

## 3. 身份模型

- **用户 (User)**：注册/登录账号，标识为「用户名 + 密码」。
- **雀士 (Player)**：全局注册表的玩家档案（名称 + 头像，头像可选、默认名称首字文字头像）。创建即自动绑定给创建者；可编辑、可解绑。
- **绑定规则**：一个用户可绑定多个雀士；一个雀士至多被一个用户绑定；被绑定的雀士需先由当前用户解绑，才能被其他用户绑定。绑定 = 「所有权与管理权」，不限制牌局里能否使用它。
- **临时雀士**：仅单局有效的玩家占位（自定义名称），游客与登录用户都能用，局终即弃、不持久化、不纳入统计。
- **雀士名称**：不强制全局唯一（靠 id 区分），同一局内不可重复。
- **开局选人**：主机可搜索并加入任意全局雀士（不论绑定给谁）+ 临时雀士；同一局内雀士不可重复。

## 4. 计分风盘（核心）

### 4.1 开局流程
1. 选择游戏模式：四人 / 三人 / 二人。
2. 加入雀士（任意全局雀士 + 临时雀士，局内不可重复）。
3. 位置调整 / 随机分位。
4. 规则确认（预填「规则默认设置」，可临时覆盖，仅本局有效；游客也可改）。

### 4.2 风盘展示信息
游戏模式、场风局数、各家自风、庄家、本场数、供托（场托）；每位雀士位置的点数居中显示，点击素点数字切换立直状态。

### 4.3 立直
点击素点数字切换立直状态，再次点击取消。立直时置放 1000 点立直棒（计入供托），块区背景变蓝显示立直状态。

### 4.4 结算入口
每个座位自带「荣和 / 自摸 / 罚符」按钮，点击预选该座位并进入对应结算面板（面板随该座位方位旋转：上 180°/左 90°/下 0°/右 −90°）；「流局」按钮位于中央块区。

### 4.5 点数计算
- **基本点** = 符 × 2^(番+2)，向上取整到百位后按亲/子系数支付。
- **番/符输入**：通过「番符得点表」弹窗点选（表格自动区分亲家/子家、荣和/自摸并展示对应分数）。番为数字（1~13、26、39、52、65、78）；番 1–4 需选符（标准档位 20/25/30/40/50/60/70/80/90/100/110），番 5 及以上不选符、满贯档位由番数自动推导。
- **满贯封顶**：基本点上限 2000（满贯）。4番40符、3番70符及以上强制满贯。
- **切上满贯**（默认否）：开启时 4番30符、3番60符（基本点 1920）进位为满贯。
- **满贯档位**：

| 档位 | 番数 | 基本点 | 子家得点（荣和） | 亲家得点（荣和） |
|---|---|---|---|---|
| 满贯 | 5番 / 切上 | 2000 | 8000 | 12000 |
| 跳满 | 6–7番 | 3000 | 12000 | 18000 |
| 倍满 | 8–10番 | 4000 | 16000 | 24000 |
| 三倍满 | 11–12番 | 6000 | 24000 | 36000 |
| 役满 | 13番 | 8000 | 32000 | 48000 |
| 双倍役满 | 26番 | 16000 | 64000 | 96000 |
| 三倍役满 | 39番 | 24000 | 96000 | 144000 |
| 四倍役满 | 52番 | 32000 | 128000 | 192000 |
| 五倍役满 | 65番 | 40000 | 160000 | 240000 |
| 六倍役满 | 78番 | 48000 | 192000 | 288000 |

- **亲/子系数**：
  - 荣和：亲家荣和放铳者付 6×基本点；子家荣和放铳者付 4×基本点。
  - 自摸（四麻）：亲家自摸每家付 2×；子家自摸亲家付 2×、其余子家各付 1×。
  - 自摸（三麻）：亲家自摸每家付 2×；子家自摸亲家付 2×、另一子家付 1×。
  - 自摸（二麻）：对家全额支付（等同荣和，亲 6× / 子 4×）。
- **本场加成**：每本场加收 300（四麻/二麻）或 200（三麻），荣和由放铳者付、自摸由各家分摊。
- **供托**：立直棒（1000/根）+ 本场棒。和牌者全取；多家荣和按「头跳」。

### 4.6 结算四类详情
1. **荣和**：选定和牌者 + 放铳者 + 番符；可选多家荣和（二家/三家）。多家时各家分别算点，供托与本场棒按「头跳」归最先和牌者（从放铳者逆时针），其余和牌者只拿基础点数。
2. **自摸**：选定和牌者 + 番符，按亲/子系数分摊。
3. **流局**：
   - **不听罚符**：标记各家「听牌/不听」，不听者共凑 3000 点由听牌者均分（0 家或 4 家听牌则无）；庄家连庄按亲家是否听牌判定。
   - **途中流局**：只记一种（不细分九种九牌/四风连打等；三麻/二麻同样只记一种），不结算点数，本场 +1、连庄。
   - **流局满贯**：指定某家按自摸满贯计（不再算不听罚符），本场 +1、庄家按听牌判定。
4. **罚符**：选定雀士 + 罚点数（8000/12000/16000/24000/32000 五个满贯档位值），罚点均分给其他玩家；罚符后本场 +1、庄家连庄。

### 4.7 局面自动推进
场风/局数/庄家/本场由结算结果自动推进：
- 庄家荣和/自摸 → 本场 +1、庄家不变。
- 闲家荣和/自摸 → 换庄、本场清零、局数 +1（局数 > 4 则场风 +1）。
- 流局 → 本场 +1，庄家按亲家听牌判定连庄。

### 4.8 终局与顺位
- **手动终局**：顶栏「终局」按钮点击弹确认框 → 打开「对局结束」面板；登录用户在面板内点「终局并保存」落库，游客「关闭」。
- **击飞**（默认是）：任一家点数 < 0 立即终局；0 点不算；负数计入结算。
- **不满返点延局**（默认是）：终局最后一局结束，无人达返点 → 加打一圈（东风战南入、半庄战西入）。
- **终局第一无限连庄**（默认否）：终局最后一局庄家和牌时——未达第一名强制连庄；是第一名则看此开关（是=连庄、否=结束）。
- **顺位**：按素点从高到低排；同分时按东一局起家的初始座次（东→南→西→北，亲家优先）打破平局。
- **得点** = (素点 − 返点) / 1000 + TOP赏 + 马点；TOP赏 = (返点 − 基础分) × 人数 ÷ 1000 归第一名（四人 +20、三人 +15、二人 0）；「是否保留一位小数」为设置项（默认保留）。
- **完场剩余供托**归第一名。

### 4.9 进行中牌局
支持保存/恢复：手机息屏或退出后，未打完的牌局可恢复继续。

## 5. 牌局录分（快速录分，需登录）

跳过逐手结算、直接录入终局结果的快速入口，与「计分风盘」共享牌局与统计（同一张牌局/参与人表）。

### 5.1 录入流程
1. 选择游戏模式：四人 / 三人 / 二人。
2. 每家座位选择一个已注册雀士（不允许临时雀士，同一雀士不能占多个座位）。
3. 录入各家终局素点。
4. 选择基础分（校验总分用）、返点与马点（计算得点用），默认值随模式联动；马点支持预设与自定义（自定义受 §5.2 的整数/个数校验）。
5. 保存：提交时校验总分，通过后落库并计入统计。

### 5.2 校验规则
- **总分守恒**：Σ素点 必须严格等于 基础分 × 人数（四人/二人 100000、三人 75000），零容差；不等则拒绝并报出具体差额。
- **允许负数**：素点可为负（击飞场景）。
- **100 整数倍**：素点、基础分、返点必须为 100 的整数倍；马点为整数（千点单位），个数须等于座位数。
- **让分**：不做逐家让分录入，仅统一基础分；线下让分自行处理（总分守恒，校验仍成立）。

### 5.3 得点与顺位
保存时复用计分风盘的终局算法：得点 = (素点 − 返点) / 1000 + TOP赏 + 马点；TOP赏 = (返点 − 基础分) × 人数 ÷ 1000 归第一名；顺位按素点从高到低、同分按录入座位顺序打破平局。

### 5.4 与计分风盘的关系
牌局录分的牌局不产生任何逐手结算记录，落库即「已终局」；因此其手级统计指标（和牌率 / 放铳率 / 自摸率 / 立直率 / 平均番数）为 0，仅牌局级指标（牌局数 / 顺位 / 总得点 / 净得点 / 击飞次数）正常累计。

## 6. 规则设置（两层）

- **第一层**：个人中心 → 规则默认设置，按四人/三人/二人分别保存（仅登录用户）。
- **第二层**：每次开局时临时覆盖（预填默认值、仅本局有效；游客也可临时改，但不保存默认）。

| 参数 | 类型/选项 | 四人默认 | 三人默认 | 二人默认 |
|---|---|---|---|---|
| 局数 | 东风战 / 半庄战 / 一庄战 / 无限庄战 | 半庄战 | 半庄战 | 半庄战 |
| 基础分 | 整数（点数） | 25000 | 25000 | 50000 |
| 返点 | 整数（点数） | 30000 | 30000 | 50000 |
| 本场点棒 | 整数（点数） | 300 | 200 | 300 |
| 不听罚符 | 整数（点数） | 3000 | 3000 | 3000 |
| 不满返点延局 | 是 / 否 | 是 | 是 | 是 |
| 番缚 | 一番缚～五番缚 | 一番缚 | 一番缚 | 一番缚 |
| 切上满贯 | 是 / 否 | 否 | 否 | 否 |
| 击飞 | 是 / 否 | 是 | 是 | 是 |
| 终局第一无限连庄 | 是 / 否 | 否 | 否 | 否 |
| 马点 | 顺位附加分（千点单位） | 10-5（+10/+5/−5/−10） | +10/0/−10 | +10/−10 |
| 得点保留一位小数 | 是 / 否 | 是 | 是 | 是 |

> 注：番缚可选一番缚～五番缚（默认一番缚）；番缚仅记录、不校验、不做输入提醒。
> 注：马点在「风盘开局」与「牌局录分」支持预设 + 自定义；「规则默认设置」仅预设（自定义不随默认持久化）。

## 7. 数据统计（需登录）

顶层分四块，其中我的创建/数据广场/雀士数据按四人/三人/二人划分（顶部用分段控件切换，默认四人），役满墙不按模式划分：

1. **我的创建**：我作为主机创建的牌局列表，含进行中（带角标，点击恢复进计分风盘）与已终局（点击进牌局详情）。
2. **数据广场**：所有已终局牌局按时间倒序公开展示（无隐私设置，见 ADR-0002）。点击进牌局详情（与「我的创建」共用一个详情页）。
3. **雀士数据**：排行榜 + 详情页两层。排行榜每行显示排名、头像、名称、当前排序指标、牌局数、平均顺位；点击进雀士详情页。主排序「总得点」降序，可切换「平均顺位」升序、「牌局数」降序；并列取同名次；默认仅显示有牌局数记录的雀士；支持搜索雀士、选择自己绑定的雀士、分页。
4. **役满墙**：全局公开的役满晒图墙，记录「某雀士在某时刻胡出某役满」（雀士 + 发生时刻 + 照片 + 役种）。任意登录用户可为任意全局雀士记录，上传者可删自己这条；照片 1~3 张（jpg/png ≤5MB，前端压缩）；役种为固定清单（16 个）+「其它」自由填写。

**牌局详情（共用）**：整局逐局结算记录 + 终局分数/顺位走势。

**统计指标**（每雀士、按模式分开，分牌局级与手级两类）：

| 层级 | 指标 | 定义 |
|---|---|---|
| 牌局级 | 牌局数 | 参与并终局的牌局数 |
| 牌局级 | 平均顺位 | Σ顺位 ÷ 牌局数 |
| 牌局级 | 顺位分布 | 1/2/3/4 位次数 |
| 牌局级 | 总得点 | Σ 每牌局得点（含马点） |
| 牌局级 | 净得点 | Σ (素点−返点)/1000（不含马点） |
| 牌局级 | 击飞次数 | 被击飞次数 |
| 手级 | 和牌数 / 和牌率 | 和牌次数；和牌率 = 和牌次数 ÷ 手数 |
| 手级 | 自摸数 / 自摸率 | 自摸次数；自摸率 = 自摸次数 ÷ 和牌次数 |
| 手级 | 荣和数 | 荣和次数 |
| 手级 | 放铳数 / 放铳率 | 放铳次数；放铳率 = 放铳次数 ÷ 手数 |
| 手级 | 立直数 / 立直率 | 立直次数；立直率 = 立直次数 ÷ 手数 |
| 手级 | 平均番数 | 和牌番数之和 ÷ 和牌次数 |

## 8. 个人中心（需登录）

### 8.1 页面结构
个人中心 = 「资料 hub + 子页」结构：资料头（文字头像 + 用户名 + 个性签名）+ 子项入口（雀士管理 / 规则默认设置 / 修改密码 / 意见反馈）+ 底部「退出登录」。

### 8.2 登录 / 注册（未登录态）
未登录打开个人中心 → 显示登录/注册页。登录：用户名 + 密码；注册：用户名 + 密码 + 确认密码。无邮箱/手机、无找回密码、无第三方登录（v1）。

### 8.3 个性签名
文本字段，≤ 100 字；资料头点击进「编辑签名」子页。

### 8.4 雀士管理
- 我的雀士列表（头像 + 名称），每行「编辑」「解绑」；顶部「+ 创建雀士」。
- 创建：名称 + 头像（可选，jpg/png ≤ 2MB；不传则用名称首字文字头像），创建即绑定给创建者。
- 绑定雀士：入口进全局搜索，列出未绑定的雀士，点「绑定」获得所有权（支持绑定他人已解绑的雀士）。
- 编辑仅限自己绑定的雀士（绑定 = 所有权/管理权）。

### 8.5 规则默认设置
见第 6 节。界面为顶部「四人/三人/二人」分段切换 + 一套 12 参数表单，每模式独立保存；「恢复默认」按钮。

### 8.6 修改密码
旧密码 + 新密码 + 确认新密码（需先验证旧密码）。

### 8.7 意见反馈
建议内容（必填，多行）+ 联系方式（选填，自由文本），提交后存入数据库。

## 9. 数据模型（实体）

- **用户**：id、用户名、密码（哈希）、个性签名、注册时间。
- **雀士**：id、名称、头像、绑定用户 id（可空）。
- **牌局**：id、创建者（用户，非空）、模式、规则快照、状态（进行中/已终局）、起止时间。
- **结算记录**：牌局 id、局序号、结果类型（荣和/自摸/流局/罚符）、涉及雀士与点数变动、番符、本场、供托、立直状态等。
- **意见反馈**：id、用户、建议内容、联系方式（可空）、时间。
- **役满记录**：id、雀士、役满役种（固定清单或「其它」+自由文本）、发生时刻、照片（1~3 张文件名）、上传者、创建时间。

## 10. 已确认的补充约定

以下 8 项原为待定，已在需求确认阶段全部定案，并已并入各节：

1. 番缚仅记录、不校验、不做输入提醒（§6）。
2. 雀士名称不强制全局唯一，靠 id 区分（§3）。
3. 头像 jpg/png，≤ 2MB（§8）。
4. 个性签名 ≤ 100 字（§8）。
5. 修改密码需验证旧密码（§8）。
6. 意见反馈联系方式为自由文本（§8）。
7. 排行榜并列同名次、默认仅显示有局数记录的雀士、支持分页（§7）。
8. 三麻/二麻途中流局均只记一种（§4.6）。
