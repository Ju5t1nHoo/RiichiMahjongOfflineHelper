# 役满照片存本地文件系统（volume），不入库、不上对象存储

役满墙的「上传照片」是全新能力。选择把照片二进制写到 api 容器的 `/data`（docker-compose 挂 volume），数据库只存文件路径；不存 base64、也不引对象存储。

理由：单张手机照常 1~5MB，base64 存 Postgres 会让 DB 快速膨胀、备份变重、出图需全量读；接 S3/MinIO 对自托管线下小工具运维过重。本地文件 + volume 介于两者之间——DB 干净、零新增依赖、单机够用。

代价：照片随这台机（volume），换机/重建需连同 volume 迁移；多实例水平扩展时本地文件不共享（当前单机部署无此需求）。前端上传前压缩（jpg/png、单张 ≤5MB）控制体积。
